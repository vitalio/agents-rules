# Description: Unique anchor verification, documentation sync, and pre-commit checks/tests
- **Edit & pre-commit verification:** When editing files programmatically, verify that each search anchor occurs uniquely (`count == 1`) before writing, prefer targeted `text.replace(old, new, 1)` patches over rewriting entire multi-hundred-line files as a single literal, validate all search anchors and syntax in memory before writing any file to disk (so a failed check leaves the working tree untouched), and avoid raw multiline strings that could break the chat Markdown fence. Keep project documentation and user-facing help in sync within the same commit when changing behavior or options. Before committing, always run syntax/linter checks on modified files and run the project's local unit test suite so untested or broken code is never committed.
